# docs/

プロジェクトの進行に伴い成長・更新されるドキュメントを管理するディレクトリ。

## 目的

コードを読めば分かる仕様（API・型・レジスタ定義）はここには書かない。
ドキュメントとして残しているのは「**コードからは読み取れない情報**」のみ:

- 設計判断の why（なぜこの構成を選んだか）
- データシートと実装の対応関係（換算式の根拠、データシートの記述と食い違う実測挙動）
- 過去のバグ事例とその対策（踏むと痛いトラップ）
- 運用ルール（実機での検証手順、I2C の環境設定）

利用者向けの説明（インストール・使い方・API 一覧・既知の制限）は、`docs/` ではなくルートの [README.md](../README.md) に置く。

## 含めるべき内容

| カテゴリ | ファイル例 | 内容 |
|---|---|---|
| アーキテクチャ | `architecture.md` | モジュール構成（driver / registers / field）と責務分離の意図 |
| ハードウェア仕様 | `hardware.md` | 配線、I2C トランザクションの形、データシートのレジスタマップと実装の対応 |
| 意思決定記録 | `decisions/` | ADR（Architecture Decision Records）形式での設計判断の記録 |
| 運用手順 | `operations.md` | 実機での検証手順、I2C の有効化・バス速度の設定 |

## 含めるべきでない内容

- **不変の方針・規約** — コーディングスタイル、命名規則等は `.claude/rules/` で管理する
- **タスク管理** — issue や `.claude/plans/` で管理する
- **機密情報** — APIキー、パスワード等は絶対に含めない

## 運用ルール

- 新しい機能やレジスタ対応を追加した際は、関連するドキュメントも同時に更新する
- ファイル名は `kebab-case.md` とする
- 図表が必要な場合は Mermaid 記法を使用し、画像ファイルの追加を避ける
